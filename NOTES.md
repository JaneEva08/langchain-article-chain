# Заметки по ДЗ VPf05 «Цепочки запросов (Chains)»

Курс «Профессия вайб-кодер», модуль 7. Разбор и доработка: 24.10.2026.

## Разбор урока

- Цепочка запросов — последовательность связанных обращений к модели: вывод одного звена становится входом следующего.
- Зачем: одна большая задача в одном промпте даёт слабый результат; цепочка передаёт на каждом шаге только нужные данные и задаёт порядок действий.
- Примеры: статья по нескольким источникам (читать → анализ цели → ключевые данные → синтез); ассистент поддержки (готовый ответ → суть обращения → развёрнутый ответ).
- В уроке: генератор Telegram-ботов на LangChain, цепочка из 4 звеньев (анализ → подбор инструментов → структура кода → код) + статическое ревью.
- Компоненты LangChain: Prompt Template, Chains, Tools. В примере использованы первые два.

### Требования ДЗ

1. Своя цепочка из 3–4 звеньев для конкретной задачи.
2. Описать логику шагов.
3. Реализовать в коде на Python с LangChain.
4. Минимальная структура: анализ задачи → подбор инструментов → реализация → проверка/ревью.
5. Сдача: ссылка на GitHub, или zip, или скриншоты работы цепочки.

Уровней нет. Куратор, судя по формату, смотрит: есть ли цепочка из 3–4 звеньев, видна ли логика шагов, работает ли она (скриншоты запуска).

### Решения

- Задача цепочки — генерация статьи по теме. Это прямо названный в ДЗ пример, результат читается без запуска дополнительных сервисов.
- Свои рабочие проекты не берём: учебный пример не смешиваем с ними.
- Замены: Cursor → Claude Code; OpenAI → aiprimetech (`gpt-6-luna`, OpenAI-совместимый, через `OPENAI_BASE_URL`).
- Из LangChain используется `langchain-core` (шаблоны, `|`-цепочки, `RunnableLambda`); вызов модели идёт напрямую через клиент `openai`, как в уроке.
- Польза вне курса: паттерн «анализ → план → черновик → ревью с дешёвой локальной проверкой» переносится на контент-завод и ИИ-обработку заявок.

### Решения, принятые мной

- Ревью двухуровневое, как в уроке: бесплатная локальная проверка, LLM-ревью только при проблемах. Исправление принимается, только если замечаний стало меньше (иначе ревью могло бы ухудшить текст).
- Результаты звеньев сохраняются в `*.steps.json`: видно, что именно передавалось между звеньями.
- `langchain-core` вместо полного `langchain`: нужны только шаблоны и `|`, меньше зависимостей.
- Тесты с заглушкой LLM проверяют порядок звеньев, ревью, имена файлов, сохранение шагов и язык в промптах.

### Что не сделано

- Нет `Tools` из LangChain (поиск, файлы): задание их не требует.
- Цепочка не читает внешние источники (первый пример урока): тема подаётся строкой.
- Нет повторных попыток при сбое API и подсчёта токенов и стоимости.
