# Docker для начинающих: установка, первый контейнер и сборка образа

## Что такое Docker и зачем он нужен

Docker помогает упаковать приложение вместе с необходимыми ему компонентами — например, библиотеками и настройками — в контейнер. Благодаря этому приложение можно запускать в разных средах, не настраивая каждую из них вручную.

Контейнеры удобны для разработки и тестирования: команда может использовать одинаковое окружение на ноутбуках, тестовых серверах и в продакшене. Это снижает вероятность ситуации, когда приложение работает на одной машине, но не запускается на другой.

Контейнеры часто сравнивают с виртуальными машинами, но устроены они иначе. Виртуальная машина запускает отдельную операционную систему, а контейнер использует ядро операционной системы хоста. Поэтому контейнеры обычно легче и быстрее запускаются. При этом они не заменяют виртуальные машины во всех случаях: выбор зависит от задач и требований к изоляции.

## Образы, контейнеры и Dockerfile: основные понятия

Для начала достаточно запомнить три понятия:

- **Образ** — шаблон с приложением и его зависимостями. Например, образ Nginx содержит веб-сервер и всё необходимое для его запуска.
- **Контейнер** — запущенный экземпляр образа. Из одного образа можно создать несколько контейнеров.
- **Dockerfile** — текстовый файл с инструкциями, по которым Docker собирает образ.

Удобная аналогия: образ — это рецепт, контейнер — приготовленное по рецепту блюдо, а Dockerfile — текст самого рецепта.

## Установка Docker и проверка работы

Выберите способ установки для вашей системы:

- **Windows и macOS:** установите Docker Desktop, следуя официальной инструкции Docker для вашей версии системы.
- **Linux:** воспользуйтесь официальной инструкцией Docker для вашего дистрибутива. Шаги установки и настройки прав могут различаться.

После установки откройте терминал и проверьте, что команда Docker доступна:

```bash
docker --version
```

Затем убедитесь, что Docker действительно работает, запустив тестовый контейнер:

```bash
docker run hello-world
```

При первом запуске Docker может скачать образ `hello-world`. Если команда завершилась успешно, в терминале появится приветственное сообщение.

## Запускаем и управляем первым контейнером

Запустим веб-сервер Nginx в фоновом режиме и сопоставим порт `8080` на компьютере с портом `80` контейнера:

```bash
docker run -d -p 8080:80 --name my-nginx nginx
```

Здесь:

- `-d` запускает контейнер в фоне;
- `-p 8080:80` направляет запросы с порта `8080` на компьютере на порт `80` внутри контейнера;
- `--name my-nginx` задаёт контейнеру имя;
- `nginx` — образ, который Docker скачает, если его ещё нет на компьютере.

Откройте в браузере адрес `http://localhost:8080`. Если всё настроено правильно, появится стартовая страница Nginx.

Посмотреть работающие контейнеры можно так:

```bash
docker ps
```

Команда `docker ps -a` показывает также остановленные контейнеры:

```bash
docker ps -a
```

Чтобы остановить контейнер, выполните:

```bash
docker stop my-nginx
```

Остановка не удаляет контейнер. Если он больше не нужен, его можно удалить:

```bash
docker rm my-nginx
```

## Собираем образ и запускаем приложение

Создадим небольшое приложение на Python. В отдельной папке сохраните файл `app.py`:

```python
print("Привет из Docker!")
```

Рядом создайте файл `Dockerfile` без расширения. Добавьте в него инструкции:

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY app.py .
CMD ["python", "app.py"]
```

Здесь `FROM` задаёт базовый образ с Python, `WORKDIR` — рабочую папку внутри контейнера, `COPY` копирует файл приложения, а `CMD` определяет команду запуска.

Откройте терминал в папке с обоими файлами и соберите образ:

```bash
docker build -t my-app .
```

Параметр `-t my-app` задаёт образу имя, а точка в конце указывает Docker использовать текущую папку как контекст сборки.

Запустите приложение:

```bash
docker run --rm my-app
```

В терминале появится сообщение `Привет из Docker!`. Параметр `--rm` автоматически удалит контейнер после завершения. Сам образ `my-app` при этом останется.

## Частые ошибки и первые полезные привычки

Если контейнер не запускается, начните с простых проверок:

- Убедитесь, что Docker запущен. Для Docker Desktop проверьте, что приложение завершило запуск.
- Проверьте выбранные порты. Если порт `8080` уже занят, укажите другой, например `8081`: `-p 8081:80`.
- Посмотрите сообщения приложения с помощью `docker logs`. Например, для контейнера Nginx: `docker logs my-nginx`.
- Если контейнер завершился, проверьте его статус через `docker ps -a`.

Полезно также регулярно удалять ненужные контейнеры и следить за образами, которые больше не используются. Конфигурацию сборки приложения храните в `Dockerfile`: так её проще повторить и передать другим участникам команды.

## Заключение

Docker позволяет запускать приложения в предсказуемом окружении, а основные понятия легко освоить на практике: образ служит шаблоном, контейнер запускает приложение, а Dockerfile описывает сборку образа. Установите Docker, проверьте его командой `docker run hello-world`, запустите Nginx и соберите образ собственного приложения.
