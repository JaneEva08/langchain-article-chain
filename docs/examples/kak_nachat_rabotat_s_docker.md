# Docker для начинающих: установка, первые контейнеры и основные команды

## Что такое Docker и зачем он нужен

Docker — платформа для запуска приложений в контейнерах. Контейнер упаковывает приложение вместе с необходимыми библиотеками и настройками, чтобы его было проще запускать в разных средах: например, на компьютере разработчика, тестовом сервере и в облаке.

Контейнеры и виртуальные машины решают похожую задачу — изолируют программы друг от друга, — но устроены по-разному:

- **Виртуальная машина** запускает отдельную операционную систему поверх основной. Это требует дополнительных ресурсов и обычно занимает больше времени.
- **Контейнер** использует ядро операционной системы хоста, но изолирует процессы и их окружение. Обычно он запускается быстрее и занимает меньше места.

Контейнеры не заменяют виртуальные машины во всех случаях: уровень изоляции и возможности у этих технологий различаются. Но Docker особенно удобен, когда нужно:

- запустить приложение без ручной установки его зависимостей на компьютер;
- использовать одинаковое окружение при разработке и тестировании;
- быстро поднять сервис, например базу данных или веб-сервер;
- подготовить приложение к развёртыванию на сервере.

## Основные понятия: образ, контейнер и Dockerfile

В Docker часто встречаются три понятия:

- **Образ** — шаблон, по которому создают контейнеры. В нём находятся приложение, необходимые файлы и сведения о том, как его запускать.
- **Контейнер** — запущенный экземпляр образа. Контейнеры могут создаваться и удаляться, а исходный образ при этом остаётся.
- **Dockerfile** — текстовый файл с инструкциями для сборки собственного образа.

Представьте, что образ — это рецепт, а контейнер — приготовленное по нему блюдо. По одному рецепту можно сделать несколько порций. Аналогично по одному образу можно запустить несколько контейнеров с одинаковым приложением.

Например, образ веб-сервера можно скачать один раз, а затем запустить на его основе контейнер. Если приложение меняется, образ пересобирают, а новые контейнеры создают уже из обновлённого образа.

## Установка Docker и проверка работы

Способ установки зависит от операционной системы:

- **Windows и macOS:** обычно устанавливают Docker Desktop с официального сайта Docker. На Windows может понадобиться включить WSL 2 и установить соответствующий компонент. Следуйте подсказкам установщика.
- **Linux:** устанавливают Docker Engine по инструкции для своего дистрибутива. Иногда для настройки нужны права администратора. Добавление пользователя в группу `docker` упрощает работу без `sudo`, но эта группа предоставляет значительные привилегии — учитывайте это при настройке системы.

После установки откройте терминал и проверьте, что команда доступна:

```bash
docker --version
```

Затем запустите тестовый контейнер:

```bash
docker run hello-world
```

При первом запуске Docker может скачать образ `hello-world`. Если всё настроено правильно, в терминале появится приветственное сообщение.

Если команда не запускается, проверьте следующее:

1. Запущен ли Docker Desktop или сервис Docker Engine.
2. Не требуется ли перезапустить терминал или компьютер после установки.
3. Доступна ли команда `docker` в командной строке.
4. Есть ли у пользователя необходимые права доступа.
5. Завершена ли настройка WSL 2 — если вы работаете в Windows.

Точный текст ошибки поможет определить причину. Например, сообщение о недоступности сервера Docker часто означает, что сам сервис ещё не запущен.

## Первый контейнер: запуск, просмотр и остановка

Команда для проверки установки одновременно показывает базовый принцип работы:

```bash
docker run hello-world
```

Теперь запустим веб-сервер Nginx в фоновом режиме и свяжем его порт с портом компьютера:

```bash
docker run -d --name my-nginx -p 8080:80 nginx
```

Здесь `-d` запускает контейнер в фоне, `--name` задаёт ему имя, а `-p 8080:80` связывает порт `8080` на компьютере с портом `80` внутри контейнера. Откройте в браузере `http://localhost:8080`: должна появиться стартовая страница Nginx. При первом запуске Docker скачает образ, если его ещё нет на компьютере.

Посмотреть работающие контейнеры можно так:

```bash
docker ps
```

Команда покажет, среди прочего, имя контейнера, его состояние и сопоставленные порты. Чтобы увидеть также остановленные контейнеры, используйте:

```bash
docker ps -a
```

Остановить Nginx можно по заданному имени:

```bash
docker stop my-nginx
```

Остановка не удаляет контейнер: его данные и настройки сохраняются, и его можно снова запустить командой `docker start my-nginx`. Чтобы удалить остановленный контейнер, выполните:

```bash
docker rm my-nginx
```

Итак, остановка прекращает работу контейнера, а удаление убирает сам контейнер. Образ, на основе которого он был создан, при этом остаётся.

## Работа с образами и полезные команды

Образы часто хранятся в реестрах, например Docker Hub. Скачать образ можно командой:

```bash
docker pull nginx
```

Посмотреть образы, уже сохранённые на компьютере, можно так:

```bash
docker images
```

Если образ больше не нужен и не используется контейнерами, его можно удалить:

```bash
docker rmi nginx
```

При запуске контейнеров полезны следующие параметры:

- `-d` — запустить контейнер в фоне: `docker run -d nginx`.
- `-p` — сопоставить порт компьютера с портом контейнера: `docker run -p 8080:80 nginx`.
- `--name` — задать контейнеру понятное имя: `docker run --name site nginx`.
- `-it` — запустить интерактивный процесс и подключить к нему терминал. Например, `docker run -it ubuntu bash` открывает командную оболочку Ubuntu внутри контейнера. Выйти из неё можно командой `exit`.

Назначение параметров и доступные варианты можно уточнить в справке:

```bash
docker --help
docker run --help
```

## Запуск собственного приложения с помощью Dockerfile

Создадим небольшое веб-приложение на Python. Для этого понадобятся два файла в одной папке.

Файл `app.py`:

```python
from http.server import BaseHTTPRequestHandler, HTTPServer

class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        self.send_response(200)
        self.send_header("Content-type", "text/plain; charset=utf-8")
        self.end_headers()
        self.wfile.write("Приложение работает в Docker!".encode("utf-8"))

HTTPServer(("0.0.0.0", 8000), Handler).serve_forever()
```

Рядом создайте файл с именем `Dockerfile` — без расширения:

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY app.py .
EXPOSE 8000
CMD ["python", "app.py"]
```

В Dockerfile используются инструкции:

- `FROM` задаёт исходный образ, на котором будет основан новый. Здесь это образ Python.
- `WORKDIR` выбирает рабочую папку внутри образа.
- `COPY` копирует файл приложения в эту папку.
- `RUN` выполняет команду во время сборки образа. Например, с её помощью устанавливают зависимости: `RUN pip install -r requirements.txt`.
- `EXPOSE` указывает, какой порт приложение использует внутри контейнера. Эта инструкция сама по себе не открывает порт на компьютере.
- `CMD` задаёт команду, которая запускается при старте контейнера.

В примере нет зависимостей, поэтому `RUN` не требуется. Если приложение использует сторонние библиотеки, их обычно перечисляют в файле `requirements.txt`, копируют его в образ и устанавливают с помощью `RUN pip install -r requirements.txt`.

Находясь в папке с файлами, соберите образ:

```bash
docker build -t my-python-app .
```

Параметр `-t` задаёт образу имя `my-python-app`, а точка в конце указывает Docker использовать текущую папку как контекст сборки.

Запустите приложение:

```bash
docker run -d --name my-python-app-container -p 8000:8000 my-python-app
```

Проверьте его в браузере по адресу `http://localhost:8000` или командой:

```bash
curl http://localhost:8000
```

Чтобы завершить работу приложения и удалить контейнер:

```bash
docker stop my-python-app-container
docker rm my-python-app-container
```

## Безопасность и рекомендации для новичков

Даже при работе с простыми учебными контейнерами полезно соблюдать несколько правил:

- Загружайте образы из доверенных источников и внимательно проверяйте название и тег. Похожие названия могут принадлежать разным авторам.
- Не записывайте пароли, токены и другие секреты в Dockerfile или файлы, которые попадают в образ. Собранный образ может быть передан другим людям или опубликован.
- Удаляйте ненужные остановленные контейнеры и образы: они занимают место на диске.
- Открывайте только нужные порты и не выдавайте контейнеру лишние права.
- Не храните важные данные только в файловой системе контейнера. При удалении контейнера такие данные могут пропасть.

Для сохранения данных изучите **тома Docker**. Том позволяет хранить файлы отдельно от контейнера и использовать их повторно, даже если контейнер удалён и создан заново.

## Заключение

Docker помогает запускать приложения в переносимых изолированных контейнерах. Для начала достаточно понять связь между образом, контейнером и Dockerfile, установить Docker и освоить основные команды: `run`, `ps`, `stop`, `rm`, `pull` и `build`. Этих знаний хватит, чтобы запустить готовый сервис и собрать контейнер для собственного небольшого приложения.
