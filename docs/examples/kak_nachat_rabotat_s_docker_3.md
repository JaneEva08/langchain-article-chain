# Docker с нуля: установка, основные команды и запуск первого приложения

## Docker: что это и зачем он нужен

Docker помогает запускать приложения в контейнерах — изолированных средах, в которых находятся само приложение и необходимые ему зависимости. Благодаря этому программу проще запускать одинаково на разных компьютерах: вместо того чтобы вручную настраивать окружение, вы используете готовый образ. В него можно включить нужную версию языка программирования, системные библиотеки, файлы приложения и инструкции по запуску.

Представьте, что приложение работает на вашем компьютере, но не запускается у коллеги: у него другая версия Python или не установлена нужная библиотека. Контейнеризация помогает уменьшить число таких проблем. Вы описываете окружение проекта в Dockerfile, собираете образ и передаёте его другому человеку или серверу. При этом для использования Docker на целевой машине обычно достаточно установить Docker и запустить контейнер из образа.

Контейнеры похожи на виртуальные машины тем, что изолируют рабочую среду. Но виртуальная машина обычно включает собственную операционную систему, а контейнер использует ядро операционной системы хоста. Поэтому контейнеры, как правило, легче и быстрее запускаются. Изоляция не означает, что контейнер полностью независим от компьютера: он использует ресурсы хоста, а параметры сети, доступ к файлам и права можно настраивать.

Docker пригодится, когда нужно:

- быстро подготовить одинаковое окружение для разработки и тестирования;
- запустить приложение, не устанавливая все его зависимости напрямую на компьютер;
- передать проект коллеге или развернуть его на сервере с меньшим риском столкнуться с разницей в настройках;
- проверить приложение в определённой версии среды, не меняя основную конфигурацию компьютера;
- запускать несколько компонентов проекта, например веб-приложение и базу данных, в отдельных контейнерах.

Контейнеры особенно удобны для воспроизводимых задач: например, для запуска тестов или локальной проверки обновлений. При этом Docker сам по себе не исправляет ошибки приложения и не гарантирует его безопасность. Образ, настройки доступа и способ хранения данных всё равно нужно выбирать осознанно.

## Установка Docker и проверка работы

Для Windows и macOS обычно устанавливают **Docker Desktop** — приложение, которое включает необходимые компоненты для работы Docker. Скачивайте его с официального сайта Docker и перед установкой проверьте системные требования для своей версии операционной системы. На Windows также могут потребоваться поддерживаемая конфигурация виртуализации и WSL 2.

На Linux обычно устанавливают **Docker Engine**. Инструкции зависят от дистрибутива, поэтому воспользуйтесь официальной документацией Docker для вашей системы. Не устанавливайте пакеты из случайных источников. Перед установкой также полезно проверить, не используется ли уже другой пакет или способ управления контейнерами: названия команд могут совпадать, а настройки — различаться.

После установки запустите Docker Desktop, если пользуетесь им, и откройте терминал. Проверьте версию клиента:

```bash
docker --version
```

Эта команда показывает версию клиента Docker. Она не всегда подтверждает, что служба, которая запускает контейнеры, доступна. Поэтому дополнительно выполните тест:

```bash
docker run hello-world
```

Если Docker работает, он при необходимости скачает образ `hello-world`, запустит контейнер и выведет сообщение об успешном запуске. После завершения тестового контейнера можно продолжать работу: он не запускает постоянно работающий сервис.

Если команда сообщает, что демон Docker недоступен, проверьте, запущено ли приложение Docker Desktop или служба Docker Engine. На Linux команда может также завершиться ошибкой доступа к Docker. В таком случае изучите официальные инструкции для своего дистрибутива и настройки разрешений. Не стоит без понимания причин запускать все команды с повышенными правами: это может расширить доступ процессов к системе.

Если загрузка образа не начинается, проверьте подключение к сети и доступность реестра. При первом запуске Docker может понадобиться скачать файлы, поэтому результат зависит от скорости соединения. Сообщения об ошибках обычно содержат сведения о проблеме: например, недоступен ли сервер, не найден ли образ или не запущена служба.

## Основные понятия: образы, контейнеры и реестры

**Образ** — это шаблон, содержащий приложение, его файлы и инструкции, необходимые для запуска. Образы обычно создают из Dockerfile или скачивают из реестра. Образ состоит из слоёв, поэтому при повторной сборке Docker может использовать уже подготовленные слои, если соответствующие инструкции и файлы не изменились. Это часто ускоряет сборку.

**Контейнер** — запущенный экземпляр образа. Один и тот же образ можно запустить несколько раз, получив несколько контейнеров. У каждого контейнера есть собственное состояние во время работы, но изменения внутри него обычно не меняют исходный образ. Если удалить контейнер, данные, которые хранились только в его файловой системе, могут пропасть. Для данных, которые нужно сохранить, применяют тома или монтирование папок хоста.

**Реестр** — хранилище, из которого можно скачивать и куда можно публиковать образы. Например, Docker Hub — общедоступный реестр с образами множества проектов. Некоторые образы доступны всем, а для других требуется авторизация. Перед загрузкой образа важно проверить, кто его опубликовал и как он обновляется.

Связь между этими понятиями можно представить так:

1. Docker получает образ из реестра, если его ещё нет на компьютере.
2. На основе образа Docker создаёт и запускает контейнер.
3. Контейнер выполняет приложение, а исходный образ остаётся неизменным.

Например, команда `docker run hello-world` использует образ `hello-world` и запускает созданный на его основе контейнер. Если образа нет локально, Docker сначала пытается получить его из настроенного реестра. При последующих запусках может использоваться уже скачанная копия.

Не путайте образ с контейнером: образ — это шаблон, а контейнер — созданный на его основе экземпляр. Не путайте также имя образа с именем контейнера. Имя образа указывают при сборке или скачивании, а имя контейнера можно задать при запуске параметром `--name`.

## Первые команды Docker

Команда `docker run` запускает контейнер на основе указанного образа. Например:

```bash
docker run hello-world
```

Если образ не найден локально, Docker попробует скачать его из реестра. После завершения процесса контейнер может остаться в списке как остановленный, если при запуске не был указан параметр `--rm`.

Часто используемые параметры:

- `-d` запускает контейнер в фоновом режиме;
- `--name` задаёт ему удобное имя;
- `-p` публикует порт контейнера на компьютере;
- `--rm` удаляет контейнер после завершения.

Например, запустить контейнер в фоне и назвать его `web` можно так:

```bash
docker run -d --name web nginx
```

Образ `nginx` содержит веб-сервер. В этом примере контейнер запущен в фоне, но порт не опубликован, поэтому обратиться к веб-серверу с компьютера через обычный адрес не получится. Чтобы открыть доступ через порт, добавьте параметр `-p`, например `-p 8080:80`: тогда порт `8080` на компьютере будет направлен на порт `80` в контейнере. После этого можно открыть `http://localhost:8080`.

Список работающих контейнеров показывает команда:

```bash
docker ps
```

Чтобы увидеть также остановленные контейнеры, используйте:

```bash
docker ps -a
```

В выводе обычно указаны идентификатор, образ, команда запуска, время работы, состояние, опубликованные порты и имя контейнера. Если контейнер быстро завершился, команда `docker ps` его не покажет — проверьте полный список с помощью `docker ps -a`.

Остановить контейнер можно по имени или идентификатору:

```bash
docker stop web
```

Удалить остановленный контейнер:

```bash
docker rm web
```

Если контейнер ещё работает, сначала остановите его. Для удаления работающего контейнера существует отдельный параметр, но для обычной работы безопаснее сначала явно остановить приложение и убедиться, что оно больше не требуется.

Посмотреть вывод приложения в контейнере помогут журналы:

```bash
docker logs web
```

Чтобы следить за новыми строками журнала по мере их появления, можно использовать параметр `-f`:

```bash
docker logs -f web
```

Для завершения просмотра нажмите сочетание клавиш `Ctrl+C`. Оно прекращает вывод логов в терминале, но не обязательно останавливает сам контейнер.

Если нужно узнать, какие команды и параметры доступны, выполните:

```bash
docker --help
```

Подробную справку для конкретной команды, например `docker run`, можно открыть командой `docker run --help`. Справка полезна, когда нужно уточнить назначение параметра или проверить его формат: некоторые опции могут отличаться в зависимости от команды и версии Docker.

Образы тоже можно просматривать и удалять. Например, список локальных образов показывает команда `docker images`. Удалить ненужный образ можно командой `docker rmi` с его именем или идентификатором, но образ нельзя удалить, пока он используется существующим контейнером. Перед очисткой проверьте, не нужен ли он для других проектов.

## Создание образа простого приложения

Создадим минимальное веб-приложение на Python. В отдельной папке проекта создайте файл `app.py`:

```python
from http.server import BaseHTTPRequestHandler, HTTPServer

class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        self.send_response(200)
        self.send_header("Content-type", "text/plain; charset=utf-8")
        self.end_headers()
        self.wfile.write("Привет из Docker!".encode("utf-8"))

HTTPServer(("0.0.0.0", 8000), Handler).serve_forever()
```

Приложение отвечает на HTTP-запросы текстом. Адрес `0.0.0.0` означает, что сервер принимает подключения на доступных ему сетевых интерфейсах контейнера. Если указать только `localhost` внутри контейнера, опубликованный порт может оказаться недоступным извне контейнера.

Рядом создайте файл `Dockerfile` — без расширения. В нём укажите инструкции для сборки образа:

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY app.py .
EXPOSE 8000
CMD ["python", "app.py"]
```

Здесь `FROM` задаёт базовый образ с Python, `WORKDIR` — рабочую папку внутри контейнера, `COPY` копирует файл приложения, а `CMD` указывает команду запуска. `EXPOSE` документирует порт, который приложение использует внутри контейнера. Эта инструкция сама по себе не публикует порт на компьютере: для этого при запуске нужен параметр `-p`.

Образ `python:3.12-slim` содержит облегчённый вариант среды Python версии 3.12. Тег версии помогает сделать окружение предсказуемее, чем использование изменчивого тега `latest`. Однако содержимое образа с конкретным тегом со временем тоже может обновляться, поэтому для особенно строгого контроля зависимостей применяют дополнительные способы фиксации версий.

Находясь в папке с обоими файлами, соберите образ:

```bash
docker build -t my-app .
```

Параметр `-t` задаёт образу имя `my-app`, а точка в конце означает, что текущая папка используется как контекст сборки. Контекст — это файлы, к которым Docker может обращаться во время сборки. Если указать слишком большую папку, сборка может передавать лишние данные и занимать больше времени. Поэтому обычно собирают образ из каталога проекта, где находятся только нужные файлы и папки.

Во время сборки Docker выполняет инструкции Dockerfile по порядку и выводит ход работы в терминал. Если сборка завершилась ошибкой, прочитайте сообщения рядом с первой неудачной инструкцией. Например, проблема может быть связана с неправильным именем файла, неверным расположением Dockerfile или невозможностью скачать базовый образ.

Теперь запустите приложение и свяжите порт `8000` на компьютере с портом `8000` в контейнере:

```bash
docker run --rm -d --name my-app-container -p 8000:8000 my-app
```

Формат параметра `-p` — `порт_на_компьютере:порт_в_контейнере`. Откройте в браузере адрес `http://localhost:8000` или проверьте ответ командой:

```bash
curl http://localhost:8000
```

Должно появиться сообщение «Привет из Docker!». Параметр `-d` оставляет контейнер работать в фоне, а `--rm` удалит его после остановки. Если порт `8000` уже занят другим приложением, замените только порт на компьютере, например используйте `-p 8080:8000`, а затем откройте `http://localhost:8080`.

Публикация порта делает приложение доступным через компьютер, на котором запущен Docker. В зависимости от настроек системы и сети оно может быть доступно не только локально. Для локальной проверки можно явно привязать порт к интерфейсу localhost, например `-p 127.0.0.1:8000:8000`. Не публикуйте сервис во внешнюю сеть без необходимости и понимания последствий.

Если приложение не отвечает, сначала проверьте, работает ли контейнер:

```bash
docker ps
```

Затем посмотрите его журналы:

```bash
docker logs my-app-container
```

Также проверьте, что в команде запуска указано правильное имя образа, приложение слушает порт `8000`, а порт на компьютере не занят. Когда закончите проверку, остановите контейнер:

```bash
docker stop my-app-container
```

Из-за параметра `--rm` остановленный контейнер будет удалён автоматически. Сам образ `my-app` при этом останется на компьютере, и его можно будет использовать для следующего запуска без повторной сборки.

## Безопасность и типичные ошибки

При работе с Docker полезно придерживаться нескольких простых правил:

- **Используйте доверенные базовые образы.** Проверяйте их источник и по возможности указывайте конкретную версию, например `python:3.12-slim`, а не изменчивый тег `latest`. Перед использованием неизвестного образа изучите описание, издателя и инструкции.
- **Не добавляйте секреты в образ.** Пароли, токены и ключи не следует записывать в Dockerfile или копировать в образ: они могут сохраниться в его слоях. Передавайте секреты безопасным способом, подходящим для вашей среды.
- **Ограничивайте доступ.** Публикуйте только необходимые порты и передавайте контейнеру только те файлы и права, которые действительно нужны приложению.
- **Следите за данными.** Файлы, созданные внутри контейнера, могут исчезнуть при его удалении, особенно если запуск выполнен с `--rm`. Важные данные храните в томе или в каталоге, смонтированном с компьютера.
- **Удаляйте ненужные ресурсы осознанно.** Контейнеры и образы занимают место, но перед удалением убедитесь, что они не используются и не содержат нужных данных.

Не следует считать контейнер гарантированной границей безопасности. Он помогает изолировать процессы, но настройки Docker, права контейнера, доступ к файлам и сетевые подключения влияют на уровень защиты. Не запускайте внутри контейнера недоверенные программы без оценки рисков и не передавайте им больше доступа, чем необходимо.

Если команда не сработала, проверьте типичные причины:

- **Docker не запущен.** Запустите Docker Desktop или проверьте состояние Docker Engine.
- **Порт занят.** Выберите другой порт на компьютере, например `-p 8080:8000`, и откройте `http://localhost:8080`.
- **Неверная папка сборки.** Команду `docker build -t my-app .` нужно запускать из каталога, где находится Dockerfile, либо указать правильный путь вместо точки.
- **Ошибка в имени образа или контейнера.** Сверьте имя в команде с тем, которое задали при сборке или запуске. Для поиска контейнера можно выполнить `docker ps -a`.
- **Приложение не отвечает.** Проверьте вывод контейнера командой `docker logs my-app-container`. Убедитесь, что приложение запущено и слушает ожидаемый порт.
- **Образ не скачивается.** Проверьте соединение и доступность реестра, а также правильность имени образа. Иногда сообщение об ошибке помогает определить, что проблема возникла именно при загрузке.
- **Сборка не видит файл.** Проверьте, что `app.py` находится в контексте сборки и что команда запускается из нужного каталога. Имя файла в инструкции `COPY` должно совпадать с фактическим.

## Заключение

Установив Docker, вы сможете запускать приложения в изолированных контейнерах и использовать одинаковое окружение на разных компьютерах. Разобравшись в образах, контейнерах и реестрах, попробуйте основные команды, соберите образ из Dockerfile и проверьте приложение через браузер или `curl`.

Для дальнейшей практики можно изменить текст ответа в `app.py`, пересобрать образ и запустить новый контейнер. Так вы увидите, что изменения исходного файла не обновляют уже собранный образ сами по себе: после правок нужно снова выполнить `docker build`. Полезно также научиться просматривать журналы и список контейнеров, а перед удалением проверять, где хранятся нужные данные.
