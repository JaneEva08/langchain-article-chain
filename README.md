# VPf05 — цепочка запросов (Chains) для генерации статьи

Домашнее задание: собственная цепочка из 4 звеньев на LangChain.
**Задача цепочки:** по одной теме получить готовую статью в Markdown.

## Логика шагов

```
тема → 1. analysis → 2. outline → 3. draft → 4. review → output/<тема>.md
```

| # | Звено | Вход | Выход | Роль ИИ |
|---|-------|------|-------|---------|
| 1 | `analysis_chain` — анализ задания | тема | JSON: цель, аудитория, ключевые вопросы, тон | редактор |
| 2 | `outline_chain` — подбор структуры | JSON анализа | JSON: заголовок, разделы с тезисами, вывод | контент-стратег |
| 3 | `draft_chain` — реализация | анализ + структура | статья в Markdown | автор |
| 4 | `review_chain` — проверка / ревью | замечания + статья | исправленная статья | корректор |

Каждое звено получает только нужные ему данные (исходный текст не тащится по всей цепочке),
а результат предыдущего звена — это вход следующего.

Ревью двухуровневое: сначала дешёвая локальная проверка (`minimal_review`: есть ли H1, все ли
разделы из плана, достаточный ли объём). Звено `review_chain` (запрос к LLM) вызывается
только если найдены проблемы, и исправленная версия принимается, только если замечаний стало меньше.

## Запуск

```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # впишите свой OPENAI_API_KEY
python article_chain.py "Как начать работать с Docker"
```

Результат — файл в папке `output/`. Уровень логов задаётся `LOG_LEVEL`.

## Тесты

```bash
pytest -q
```

Тесты подменяют LLM заглушкой, поэтому ключ и сеть не нужны.

> API-ключ хранится только в `.env` (он в `.gitignore`) — не вставляйте ключ в код и не коммитьте его.
